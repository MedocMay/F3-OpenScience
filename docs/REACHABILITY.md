# 可达性(Reachability)—— 设计原则与实现

> **可达性必须是物理标准,而非统计标准。**
> 模型偏好应当是可达空间的**提议器**,而不是**裁判**。

## 一、问题:护城河如何变成牢笼

本项目的飞轮是:校验失败 → 提炼模式 → **前置注入生成阶段** → 下次规避 → 拦截率下降。

这条链路的后半段有一个隐蔽的失败模式:**把校验器的能力边界,悄悄变成生成器的世界边界。**

单看「拦截率下降」无法区分两种情况:

| | 现象 | 实质 |
|---|---|---|
| A | 拦截率 ↓ | 系统学会了不再捏造 —— 真进步 |
| B | 拦截率 ↓ | 系统学会了**绕开难以校验的区域** —— 可达性坍缩 |

B 的后果是系统性的:只引用容易被索引的文献、只陈述能字面打印的数字、只提出好校验的命题。
最终收敛为「在路灯下找钥匙」,而路灯还在自己关小。

## 二、分野:两类失败在语义上根本不同

```
reject      权威登记处确证矛盾        —— 世界不允许        —— 可作为生成约束
unresolved  索引 / 校验能力未覆盖     —— 只是我们看不到    —— 不得作为生成约束
```

判据落在**证据基质的权威性**上:

| 基质 | 有权宣告"不存在"吗 | 理由 |
|---|---|---|
| arXiv ID | ✅ 有 | ID 空间稠密且权威,格式合法却解析不到 = 确证捏造 |
| CrossRef / DataCite DOI | ✅ 有 | 登记处即事实来源 |
| OpenAlex 标题匹配 | ❌ 没有 | 只是索引覆盖;匹配不到 ≠ 不存在(新预印本 / 非英语 / 小众会议) |
| 运行日志字面命中 | ❌ 没有 | 数字可能是合法推导值,而非捏造 |

**署名门槛不因此放松**:`reject` / `unresolved` / `manual` 任一存在,`all_green` 均为 `False`。
改变的只是——**它是否有资格塑造生成偏好**。

## 三、实现

| 位置 | 机制 |
|---|---|
| `coe_kernel/verify.py` | 按基质权威性判定 `failure_kind`:`fabrication` / `verification_gap` |
| `coe_kernel/kernel.py` | 报告增加 `coverage`(查了哪些基质、已知盲区、覆盖率);`all_green` 仍拦 `unresolved` |
| `memory/store.py` | ★ `inject()` **只注入 `fabrication`**;`verification_gap` 进 `capability_backlog()` |
| `coe_kernel/metrics.py` | 误拒率 / 覆盖率 / 新颖论断占比;`flywheel_health()` 判定「学习」还是「牢笼」 |
| `tests/golden/reachability_case.json` | 可达性回归集:专收「世界允许但校验器容易误杀」的论断 |

### 破牢笼的那一刀

```python
# memory/store.py :: inject()
WHERE status='active' AND lesson_class='fabrication'   # ← 校验缺口不得进入生成约束
```

校验缺口不再变成生成禁区,而是转化为**能力建设需求**:

```
UNVERIFIABLE_DERIVED_NUMBER  hits=1  → 实现推导式校验(R3):允许由日志值重算得到的数字
UNINDEXED_CITATION           hits=3  → 扩展证据基质(Semantic Scholar / PubMed / 机构库)
```

## 四、必须并读的指标

```
拦截率 ↓ + 可达率 持平/↑   = learning   真的学会了
拦截率 ↓ + 可达率 ↓        = narrowing  ⚠ 疑似牢笼
```

`flywheel_health(interception_curve, coverage_curve)` 直接给出判定。
**只报拦截率下降而不报可达率,是危险的自我欺骗。**

## 五、已修的真实缺陷

本节按发现顺序列出。它一直在变长,而每一条都是本文档已经写过的那条纪律
在实现里的又一次落空 —— 这个规律本身比其中任何一条都值得注意。

### 5.1 熔断器把「服务说没有」和「服务连不上」混为一谈

HTTP 404 是登记处成功应答的否定结论,却被计入失败计数。连查几个捏造引用即触发熔断,
系统随即丧失判定捏造的能力、一切退化为 `unresolved`,且结果依赖调用顺序。

已修:404/410 视为权威否定(不计失败、缓存保留该语义),仅网络故障计入熔断。

### 5.2 一个正则表达式判定 Maldacena 的论文不存在 — 2026-07-29

`_ARXIV_RE` 只认 2007 年后的标识格式 `2306.01234`。而 `check_arxiv` 对匹配不上的
字符串返回 `False` —— **权威否定**。于是每一条 2007 年前的 arXiv 引用都被判为捏造。

`hep-th/9711200` 是 Maldacena 的 AdS/CFT 论文,被引约两万次。本校验器称它是捏造。
不是「无法核验」,而是一个关于世界的正面断言。物理与数学的奠基文献几乎全在这个位置上。

这是本文档第二节那张表在实现里的失效:表里写着 arXiv ID **有权**宣告不存在,
因为「格式合法却解析不到 = 确证捏造」。而「格式合法」的判定权,被一个只认识两种格式
之一的正则悄悄接管了。**覆盖边界又一次被当成了世界的边界**,只不过这次的边界是一行
正则,而不是一个索引。

已修:加 `_ARXIV_OLD_RE` 认 `archive/YYMMNNN`;更要紧的是无匹配时返回 `None`(未知)
而非 `False` —— **认不出一个标识,是关于本解析器的陈述,不是关于什么存在的。**
捏造检测未受影响,`2099.99999` 仍判 `reject`。

值得记的是这个缺陷躲过了 21 条可达性回归集:里面一个旧格式 ID 都没有。
**回归集只能暴露它想到的边界。**

### 5.3 判定不幂等 — 第二条通道,2026-07-29

上文原先写着「判定现已幂等」。**那句话在第 4 层上不成立,而当时无人察觉。**

`temperature` 在代码库任何地方都没有设置过,`router.complete()` 也不传,于是用了
provider 的默认值 —— 也就是**采样**。相关性判定因此是抽签结果:同一条边界论断在
八次完全相同的调用里返回

```
0.6  1.0  0.0  1.0  0.0  0.8  0.9  0.9
```

两次越过 `REL_THRESHOLD = 0.10`。**同一条引用,这次通过,下次被拦。**

判然分明的输入是稳定的(一条张冠李戴八次全打 0.0),所以信号是真的,方差集中在真正
模棱两可的论断上。但**一个答案取决于抽签的签名门,不成其为门**。

已修:温度透传至路由,相关性调用钉死 `temperature=0`。同一条论断此后八次全打 0.8。
零温度是托管 API 所能提供的最强请求,不是确定性保证;残余方差记录在
`layers["llm_relevance"]` 里,而非被隐藏。

**5.1 修的是「不同调用顺序给出不同判定」,5.3 修的是「同一调用给出不同判定」。**
两者都是不幂等,而第一条修完之后,那句「判定现已幂等」把第二条挡在了视野之外整整
两个月 —— 一个已经写下的结论,让一个尚未检查的通道显得不必检查。

### 5.4 可复现性尚不是一项被报告的指标

本文档第四节要求拦截率与可达率并读,第九节把探索率也加了进来。**判定可复现性不在其中。**

而 5.3 表明:不重复测量,你无法区分自己拿到的是判断还是抽签。这条属性应当与误拒率、
漏放率并列被报告 —— 目前它不是,这是尚未完成的工作。

## 七、R3:证据从「字面命中」到「可重算」

### 问题
要求数字字面出现在运行日志里,会把可声称的科学压缩成「我的沙箱恰好打印过的东西」。
相对提升、绝对增益、单位换算、由两个日志量算出的第三个量 —— 全是合法且可检验的论断,
却被字符串匹配一律拒绝。

### 立场
**放宽的是证据形式,不是证明责任。** 数字仍必须可被独立重算,
只是「重算」不再等同于「这个字符串出现过」。

### 判定顺序(`coe_kernel/verify.py::verify_number`)
```
1) 日志字面命中              -> pass   kind=log
2) claim 自带 derivation,重算成立 -> pass   kind=derivation
3) 有界算子空间自动发现推导      -> pass   kind=derivation(附表达式供复核)
4) 推导式重算与声明值矛盾       -> reject failure_kind=fabrication   ← 计算是权威裁判
5) 都不成立                  -> unresolved / verification_gap
```

第 4 条是 R3 的实质:**计算说不,就是不。** 与「索引里查不到」截然不同 ——
后者只是我们看不见,前者是确证矛盾。裁判标准由此从书目学迁向计算。

### 保守性设计(防止把噪声拟合成证据)
- 只搜索 7 个**有物理/统计意义**的算子(差、和、比、积、相对变化…),**不做通用符号回归**;
- 只在日志**具名量**之间搜索,不引入任意常数;
- 声明值精度不足(小数位 < 2)直接放弃自动发现 —— 避免巧合命中。
  精度不足但合法的推导,可由作者显式提供 `derivation` 字段获得校验。

### 安全性
推导式用 **AST 白名单**求值,禁止函数调用、属性访问、下标、推导式、未知符号。
`__import__(...)` / `open(...)` / `x.__class__` / `[x for x in ...]` 全部拦截(见 `tests/test_derivation.py`)。

### 效果(可达性回归集实测)
```
覆盖率 0.429 → 0.500     可达空间扩张
误拒率 0.0   → 0.0       没有把真实误判为捏造
漏放率 0.0   → 0.0       也没有放过捏造
```
**可达率↑ 而误判率不变 —— 这是「能力扩张」而非「放水」的标志。**

## 八、R4:量纲一致性 —— 第一个与索引无关的约束

### 为什么它不同
前面所有校验都依赖**外部证据基质**:查登记处、读运行日志。它们回答的是
「有没有人记录过这件事」。量纲不同,它回答的是「**这在物理上可能吗**」:

```
准确率 + 耗时      量纲不可加      -> 世界不允许
准确率 = 1.35      超出取值域      -> 世界不允许
步数 = -3          计数为负        -> 世界不允许
```

不查任何数据库即可判定。因此量纲违反归入 **fabrication**,
是校验层第一次拥有**完全不依赖书目学的权威否定源**。

### 物理反向重塑提议器
量纲检查放在推导发现的**求值之前**:

```python
# derivation.discover()
ok, _ = dims.check_expression(expr, symbols)
if not ok: continue          # 物理上不可能的组合根本不进入候选
```

这不是"先自由拟合、再事后过滤",而是**用物理硬约束重塑搜索空间本身**。

### ★ 最关键的自我约束:歧义即未知

量纲推断依赖**命名启发式**,而命名启发式不是物理定律。
把它当成物理定律,就是在新的地方重犯同一个错误 ——
**把「我熟悉的解读」误认为「客观的约束」**。

实测撞到的真实误拒:

```
"accuracy improvement of 12.4%"
  同时命中 accuracy(概率,上界 1)与 improvement(百分比)
  武断选前者 -> 12.4 > 1 -> 判「物理不可能」
  但 12.4% 是完全合法的提升幅度
```

这是把「我误解了」当成「世界不允许」。修正原则:

| 情况 | 处理 |
|---|---|
| 单一语义命中 | 判定 |
| 多语义命中(歧义) | **返回 unknown,不下断言** |
| 有显式单位标记(如 `%`) | 用作者写下的事实消歧 |
| 无任何命中 | unknown ≠ 无量纲 —— 未知就是未知 |

同理,量纲传播中**任一操作数未知则结果未知**,绝不默认为无量纲 ——
否则推断错误会被伪装成物理结论。

该案例已固化进 `tests/golden/reachability_case.json`,由 `false_rejection_rate` 长期守护。

### 实测
```
12 个测试套件全绿
误拒率 0.0   —— 两个新增误拒陷阱均未踩中
漏放率 0.0   —— 物理否定(准确率 1.35、量纲不可加)全部拦截
```

## 九、R5:探索预算与新颖论断署名

### 补上反向缺口
此前 CoE 只看引用与数字,像「我们提出机制 X 导致 Y」这类**真正的科学主张
完全不进校验** —— 系统既不拦截也不背书,却在为整篇草稿署名。
R5 把机制性命题纳入抽取与判定(`coe_kernel/novelty.py`)。

### 新颖度决定**基质**,而非通过与否

```
命题在既有文献中有支撑  ->  引用型或计算型证据均可
索引中未见支撑          ->  必须由计算型证据背书(可复现包 / 推导 / 运行日志)
```

第二条不是放宽,而是**换了一种更硬的基质**:从书目学(有没有人说过)
转向计算(能不能被重算与复现)。这正是让系统能为
「世界允许但模型不熟悉」的东西署名的关键 —— 否则它只会退化成查重器。

★ 仍然防住 R2 的老陷阱:**索引里找不到 ≠ 该命题是新的**。
二者在证据上无法区分,因此只报 `unestablished_in_index`,绝不断言 `novel`,
并据此**提高**证据要求而非降低。

### 生成器必须自带证据
机制性命题不由校验器"放行",而由**生成器附上证据链**。
无证据的主张 -> `unresolved` -> 阻断署名。放宽的是基质,不是证明责任。

诚实边界:CoE 只校验「证据基质是否成立」,**不判断因果是否成立**。
实验是否充分证成某个机制命题,由人在署名前 GATE 复核。
该边界已写入 `KNOWN_BLIND_SPOTS`,不冒充因果裁判。

### 探索预算
低先验假设占比设下限(`OPENSCI_EXPLORATION_RATIO`,默认 0.3)。三条原则:

1. 配额是**下限**而非上限;
2. 探索**不降低证据标准** —— 低先验假设同样要过 R3/R4 的计算与物理裁判。
   鼓励探索而不设物理裁判,只会放大噪声;
3. 候选池不足时**如实报告未达成,不伪造探索项**。

### 三曲线并读

```
拦截率↓ + 可达率持平/↑ + 探索率持平/↑   = learning      真的学会了
拦截率↓ + 可达率↓                        = narrowing     ⚠ 绕开难校验区域
拦截率↓ + 可达率持平 + 探索率↓            = conservative  ⚠ 只敢走熟路
```

第三种最隐蔽:所有校验指标都好看,但系统已不再提出低先验假设 ——
退化成一台安全的平庸机器。**只看前两条曲线发现不了。**

### 实测
```
5 条机制性命题由计算型证据背书署名(含 2 条低先验探索)
其中 4 条在索引中无既有支撑 —— 系统第一次能为"文献里没有的东西"署名
探索率 0.4 ≥ 预算 0.3
13 个测试套件全绿
```

## 十、R6:领域物理可达性

R4 的量纲检查是**跨领域**的浅层约束。R6 要的是**领域内的深层约束**:
一个分子式是否可能存在、一个反应是否守恒 —— 由化学规律决定,
与任何数据库是否收录过它**无关**。

### 判据(`coe_kernel/domains/chemistry.py`)

| 判据 | 依据 | 依赖 |
|---|---|---|
| 原子守恒 | **质量守恒定律** | 零依赖 |
| 不饱和度 DoU < 0 | 氢原子超过骨架承载上限 | 零依赖 |
| 价键合法性 | 原子价上限 | 可选 RDKit |

```
2H2 + O2 -> 2H2O    原子守恒成立            plausible
H2  + O2 -> H2O     原子不守恒 {O: 1}        impossible ← 违反守恒定律
C6H12O6             DoU = 1                 plausible
C2H8                DoU = -1                impossible ← 氢超过承载上限
CH3                 DoU = 0.5(自由基)      plausible  ← 真实存在,不判死
NaCl2Fe3            含判据外元素             unknown    ← 承认判断不了
C(C)(C)(C)(C)C      五价碳                   impossible ← RDKit 价键检查
```

### 同一条纪律,第三次贯彻

R6 最容易犯的错误,还是那一个:**把判据的适用边界当成世界的边界**。

- 自由基 `CH3` 的不饱和度是半整数 —— 它**真实存在**,不得判死,只标记待确认;
- `NaCl2Fe3` 含判据外元素 —— 承认 `unknown`,不冒充结论;
- 未装 RDKit 时价键判定返回 `unknown`,理由明写「能力缺失,非物理结论」。

### 可插拔 + 默认关闭
核心保持零依赖;领域判据按 `run_verify(..., domain="chemistry")` 启用,
MVP 域(ML/CS)不受影响。biology / materials 可按同一接口扩展。

### 实测
```
14 个测试套件全绿
质量守恒、不饱和度:零依赖即可判定物理不可能
自由基、判据外元素、缺库:全部正确返回"判断不了"而非"不可能"
```
